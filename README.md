# מוקד — מערכת ניהול מתקשרים והקפצת שיחות

מערכת Web לניהול מתקשרים עבור מוקד, המחוברת לתותח שיחות (GIS). כשמגיעה שיחה,
המערכת מזהה את השלוחה ואת מספר הטלפון, מאתרת את רשומת המתקשר הקיימת, ומקפיצה
אותה אוטומטית למסך של הנציג המשויך לאותה שלוחה.

## הרצה (DEV)

דרישה יחידה: Docker.

```bash
cd caller-center
cp .env.example .env      # ערוך את הסודות לפי הצורך
docker compose up --build
```

המערכת תעלה על http://localhost:3000
(בסיס הנתונים נחשף גם על פורט 5433 למקרה שתרצי להתחבר אליו ישירות).

בהרצה הראשונה נוצרים אוטומטית (seed):
- **מנהל**: `admin` / `Admin!12345`
- **נציג לדוגמה**: `rachel` / `Agent!12345` (שלוחה 203)
- **מתקשר לדוגמה**: דוד כהן / 050-1234567

## בדיקה מהירה של ההקפצה

1. היכנס כמנהל, לחץ **סימולטור**.
2. בחלון/דפדפן אחר היכנס כנציג `rachel`.
3. בסימולטור שלח אירוע: שלוחה `203`, טלפון `0501234567` → אצל rachel תקפוץ רשומת דוד כהן.
4. שלח מספר לא מוכר → אין הקפצה, ורואים זאת ב**לוגים** עם "לא נמצא".

## מפרט הוובהוק להטמעה ב־GIS

הגדר את ה־GIS לשלוח בכל אירוע שיחה בקשת POST לכתובת:

```
POST https://<הדומיין-שלך>/api/webhook/gis
Content-Type: application/json
X-Webhook-Secret: <הערך של GIS_WEBHOOK_SECRET מקובץ .env>
```

גוף הבקשה (JSON):

```json
{
  "call_id": "מזהה-שיחה",
  "extension": "203",
  "phone": "0501234567",
  "event_type": "connected",
  "event_time": "2026-09-01T19:31:04Z",
  "direction": "outbound"
}
```

- `extension` — מספר השלוחה, לפיו נדע לאיזה נציג להקפיץ.
- `phone` — מספר המתקשר, לפיו נחפש רשומה קיימת.
- אם ה־GIS שולח שמות שדות אחרים — המתאם ב־`src/lib/gis-adapter.ts` הוא המקום היחיד לעדכן.

תשובת המערכת: `200` עם `matched`, `screen_pop`, `caller_id`. שגיאת אימות: `401`.

## מבנה

- `server.js` — שרת Next.js + Socket.IO (הקפצה בזמן אמת).
- `prisma/schema.prisma` — מודל הנתונים.
- `src/lib/` — נרמול טלפון, מתאם GIS, לוגיקת התאמה, עיבוד אירוע שיחה, auth.
- `src/app/agent/` — מסכי הנציג (כולל מסך מתקשר).
- `src/app/admin/` — ניהול נציגים, מתקשרים, שדות, לוגים, דוחות, ייבוא, סימולטור.
- `src/app/api/` — ה־API כולל הוובהוק.

## אבטחה ופרטיות (לפני פרודקשן)

- החלף `NEXTAUTH_SECRET` ו־`GIS_WEBHOOK_SECRET` לערכים אקראיים חזקים.
- הפעל HTTPS/TLS. הגבל את מקור הוובהוק (IP allowlist) בנוסף ל־secret.
- הצפן את בסיס הנתונים במנוחה + גיבויים מוצפנים.
- הגדר מדיניות שמירה (retention) ל־`rawPayload` בלוגים.
- אל תשתמש בנתונים אמיתיים בסביבת DEV.
